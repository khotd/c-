# Контрольные вопросы — Лабораторная работа №1
## Индексы и EXPLAIN ANALYZE в PostgreSQL

1. **Чем EXPLAIN отличается от EXPLAIN ANALYZE?**  
   EXPLAIN показывает только предполагаемый план (cost, estimated rows) без выполнения. EXPLAIN ANALYZE реально выполняет запрос и добавляет actual time, actual rows, loops.

2. **Что такое Sequential Scan и когда он оправдан?**  
   Полный проход по таблице. Оправдан, если нужна большая доля строк, таблица маленькая, или индекс дал бы слишком много случайного I/O.

3. **Что такое Index Scan и Index Only Scan?**  
   Index Scan: поиск TID в индексе + чтение строк из heap. Index Only Scan: все нужные данные берутся из индекса (covering), обращение к таблице не требуется (если visibility map позволяет).

4. **Что такое Bitmap Index Scan / Bitmap Heap Scan?**  
   Сначала по индексу строится bitmap TID’ов, затем страницы heap читаются упорядоченно пачками — выгодно при «среднем» числе попаданий.

5. **Что такое селективность?**  
   Доля строк, удовлетворяющих условию. Высокая селективность (мало строк) → индекс выгоден; низкая → часто Seq Scan.

6. **Почему PostgreSQL может не использовать существующий индекс?**  
   Низкая селективность, устаревшая статистика, выражение в WHERE ломает индекс (`LOWER(col)`), неверный порядок колонок составного индекса, cost Seq Scan ниже.

7. **Правило leftmost prefix для составного индекса `(a, b, c)`?**  
   Индекс полезен для `a`, `a+b`, `a+b+c`. Условие только по `b` или `c` обычно индекс не использует.

8. **Зачем partial index и expression index?**  
   Partial — индекс только на подмножество (`WHERE status='NEW'`), меньше размер. Expression — индекс по выражению (`LOWER(email)`), когда в запросе то же выражение.

9. **Почему нельзя создать индексы на все колонки?**  
   Рост размера БД, замедление записи (INSERT/UPDATE/DELETE), лишняя нагрузка на maintenance; многие индексы никогда не используются запросами.

10. **Как подтвердить, что оптимизация сработала?**  
    Сравнить EXPLAIN ANALYZE до и после: тип Scan, Execution Time, actual rows, используемый индекс — не полагаться только на факт `CREATE INDEX`.
