# Контрольные вопросы и ответы — Лаба 1
## Индексы и EXPLAIN ANALYZE

1. **Чем EXPLAIN отличается от EXPLAIN ANALYZE?**  
   **EXPLAIN** только показывает предполагаемый план выполнения (оценка cost и числа строк), запрос не выполняется.  
   **EXPLAIN ANALYZE** реально выполняет запрос и добавляет фактические метрики: actual time, actual rows, loops, Execution Time.

2. **Что такое Sequential Scan и когда он оправдан?**  
   Полный последовательный проход по всем страницам таблицы. Оправдан, если нужна большая доля строк, таблица маленькая, или поиск по индексу дал бы слишком много случайного I/O и вышел бы дороже Seq Scan.

3. **Что такое Index Scan и Index Only Scan?**  
   **Index Scan** — по индексу находятся TID (адреса строк), затем данные читаются из таблицы (heap).  
   **Index Only Scan** — все нужные колонки уже есть в индексе (covering), к таблице почти не обращаются (если visibility map позволяет). Обычно быстрее Index Scan.

4. **Что такое Bitmap Index Scan / Bitmap Heap Scan?**  
   Сначала по индексу строится bitmap подходящих TID, затем страницы таблицы читаются более упорядоченно пачками (**Bitmap Heap Scan**). Выгодно при «среднем» числе попаданий: не одна строка и не почти вся таблица.

5. **Что такое селективность?**  
   Доля строк, которые удовлетворяют условию WHERE. Высокая селективность (мало подходящих строк) → индекс обычно выгоден. Низкая (много строк) → часто выгоднее Seq Scan.

6. **Почему PostgreSQL может не использовать существующий индекс?**  
   Низкая селективность условия; устаревшая статистика; выражение в WHERE не совпадает с индексом (например `LOWER(col)` при индексе по `col`); неверный порядок колонок составного индекса; оценка стоимости Seq Scan ниже.

7. **Правило leftmost prefix для составного индекса `(a, b, c)`?**  
   Индекс полезен для условий по `a`, по `a` и `b`, по `a`, `b` и `c`. Условие только по `b` или только по `c` обычно этот индекс не использует.

8. **Зачем partial index и expression index?**  
   **Partial** — индекс только на часть строк (`WHERE status = 'NEW'`): меньше размер, точнее под частый фильтр.  
   **Expression** — индекс по выражению (`LOWER(email)`), когда в запросе используется то же выражение.

9. **Почему нельзя создать индексы на все колонки?**  
   Растёт размер БД; замедляются INSERT/UPDATE/DELETE (каждый индекс нужно обновлять); растёт стоимость maintenance (VACUUM и др.); многие индексы запросами не используются и не окупаются.

10. **Как подтвердить, что оптимизация сработала?**  
    Сравнить **EXPLAIN ANALYZE до и после**: изменился тип Scan, уменьшилось Execution Time, в плане появился нужный индекс / Index Cond. Недостаточно просто выполнить `CREATE INDEX`.
